# Page Network — architecture

Rules and audit: `PHASE4_AUDIT.md`. Operator guide: `PAGE_MANAGEMENT.md`. Tests: `PAGE_NETWORK_TESTING.md`.

## 1. Entities

```
Organization
 ├─ PageCategory ───────────┐ default editorial style + content preferences (EditorialProfile)
 ├─ PageGroup ──┐           │ group-level preferences (EditorialProfile)
 │              │ N:M (page_group_members)
 ├─ ManagedPage ┴───────────┘ one row = one page on ONE platform; own overrides (editorialIdentity + profile)
 │      │ social_account_id (UNIQUE, nullable, reference only)
 │      ▼
 ├─ SocialAccount (= Publishing Destination)  ◄─ 1:1 ─ UploadPostConnectedAccount ─ UploadPostProfile
 │                                                          (Phase 2, written by sync only)
 ├─ Creator            (a person; never a page; a creator's account cannot be a page's destination)
 └─ Campaign ── campaign_pages ──► ManagedPage
            └─ campaign_page_groups ──► PageGroup
```

| Table | New / changed | Notes |
|---|---|---|
| `managed_pages` | **extended** (ten nullable columns, four indexes) | `category_id`, `platform`, `username`, `profile_url`, `target_audience`, `language`, `editorial_identity`, `profile` (JSON), `internal_notes`, `social_account_id` (unique). Unique `(organization, platform, username)`; NULLs do not collide, so Phase 2 rows stay valid. |
| `page_categories` | new | name, slug, description, language, `default_editorial_style`, `content_preferences` (JSON), status. Unique name and slug per organization. |
| `page_groups` | new | name, slug, description, `content_preferences` (JSON), status. |
| `page_group_members` | new | `(group, page)` unique: a page may be in many groups, once in each. |
| `campaign_pages`, `campaign_page_groups` | new | relationship records only. |

Migration `20261121100000_page_network`: additive (generated by Prisma against a shadow database from the migration history, then read: no `DROP`, no change to any existing column, enum, index or row). Fresh MySQL 8.4 applies the whole chain. Rollback: the new columns and tables are unused by `main`; reverting the application code leaves them dormant.

## 2. Statuses and archiving

Categories, pages and groups use `ACTIVE | ARCHIVED` (the existing `ManagedPageStatus`). Nothing is ever deleted.

| Archive … | Effect |
|---|---|
| a category | its pages keep it (shown as archived); new pages and re-assignments cannot choose it; restorable |
| a page | read-only; cannot join groups or campaigns; it keeps its group memberships and its destination link (history stays visible) and is excluded from active counts and from a campaign's effective pages |
| a group | read-only; no longer carries its pages into campaigns |

## 3. Editorial identity

`EditorialProfile` (pure type in `@socialith/publishing/src/editorial.ts`, validated at the API with a strict schema):

| Part | Fields |
|---|---|
| text (beside the profile) | page: `editorial_identity`; category: `default_editorial_style` |
| `contentPreferences` | `formats[]` (ids of the format definitions), `topics[]`, `avoidTopics[]`, `avoidTerms[]`, `maxTextLength`, `requiresVerifiedFacts` |
| `visual` | `style`, `fonts[]`, `colors[]` (hex), `textPosition`, `aspectRatio` |
| `guidelines` | free text |
| `originality` | `similarityThresholdPct`, `lookbackPosts` |
| `ruleEnforcement` | `WARN` (default) or `BLOCK` |

**Inheritance** (`resolveEditorialIdentity`): page → group → category → built-in default, **per field**. A value is "set" only if meaningful (non-blank string, non-empty list, number in range, valid enum, any boolean); everything else inherits, so a blank field is never an override. Lists are replaced, never merged. A boolean `false` on a page overrides a category's `true`. The result carries a `sources` map (`page | group | category | default | unset`) that the dashboard shows next to every field. The group layer is applied only when a group is named (a page may be in several groups, so there is no single right one — TD-55).

Storage: an all-empty profile is stored as SQL NULL, so "inherit everything" has exactly one representation.

## 4. Editorial formats (preparation only)

`EDITORIAL_FORMATS` (served at `GET /api/page-network/formats`): short message, cinematic quote, meme layout, commentary, match/player fact card, relationship text, lifestyle tip — each with its usual aspect ratios and whether its text must rest on verified facts. Every entry is `implementation: "DEFINITION_ONLY"`: **nothing renders media or places text** in Phase 4. Phase 5 (Media Packs) and Phase 6 (Format Engine, AI Studio) read the page's effective identity and these definitions; the contract between them is the resolved profile above.

## 5. Page rules and originality

Pure functions `checkPageRules` and `checkOriginality`:

| Rule | Severity |
|---|---|
| text longer than `maxTextLength`; an avoided term (case-insensitive, Turkish dotted/dotless i folded, matched at the start of a word so suffixes are caught but "class" does not trip "ass") | WARNING; ERROR when `ruleEnforcement = BLOCK` |
| text ≥ threshold similar (word 3-gram Jaccard, the Phase 3 measure) to one of **the same page's** last N posts that went out or are going out | WARNING; ERROR when `BLOCK`; N = 0 switches it off; threshold defaults to the organization's publishing setting |
| `requiresVerifiedFacts` | INFO reminder; Socialith never claims to verify a fact |

They run in two places: `POST /pages/:id/check-text` (advisory, stores nothing) and inside the Publishing Center's validation of each publication whose destination serves an active page (message prefixed with the page name). With no rules set they add nothing, so every existing publication behaves as before. The Phase 3 *cross-page* repetition guard is separate and unchanged. There is no mass-posting and no engagement feature of any kind.

## 6. Account mapping

A page publishes only through the destination in `social_account_id`. `buildMapping` derives the state **on every read** (nothing stored) with the Publishing Center's own checks (`validateDestination` over the shared `destinationFactsOf`):

| State | Meaning |
|---|---|
| `NO_DESTINATION` | nothing linked — nothing is shown as connected |
| `READY` | no issue: connected, provider connected, profile active and not blocked, identity unchanged, same platform, not a demo account |
| `REAUTH_REQUIRED` | Upload-Post says the authorization expired |
| `DISCONNECTED` | account disconnected, gone from its profile, or the destination was switched off |
| `UNAVAILABLE` | profile removed or blocked, a different account behind the handle, platform mismatch, demo account |

Shown per page: provider, platform, account handle, authorization status, publishing capability (`canPublish` and the provider's capability list), Upload-Post profile (editors and above), last synchronization time, the issues in plain words, and a note when the Phase 2 profile mapping points at another page.

**Link rules** (`assertLinkable`): the destination must exist in the organization (404 otherwise), match the page's platform, not be a demo/seed account, not already serve another page (409 naming it), and not belong to an individual creator. A link never creates, copies or modifies a `SocialAccount`; unlinking only clears the reference. The platform of a page cannot change while a destination is linked.

## 7. Campaigns

`campaign_pages` (direct) and `campaign_page_groups` (a group). A campaign's **effective pages** = direct pages ∪ active members of active assigned groups, each listed once with every reason (`direct`, `group: X`). Assigning validates every id first (foreign, unknown, archived → nothing is assigned) and is idempotent. `GET /campaigns/:id/content?categoryId=|pageId=` returns the campaign's content that has at least one publication target on a matching page. These links record *who the campaign is for*; they publish nothing and do not restrict what may be scheduled (that stays per publication and approved in the Publishing Center).

## 9. Permissions and privacy

| | VIEWER | EDITOR | ADMIN / OWNER |
|---|---|---|---|
| read overview, pages, categories, groups, mapping, campaign pages, formats; check a text | yes | yes | yes |
| internal notes, Upload-Post profile name | **hidden** | shown | shown |
| create / edit / archive categories, pages, groups; edit identity; link destinations; assign to campaigns | no (403) | no (403) | yes |

Organization isolation is in every query (another organization's id is a 404, never a 403). No page endpoint returns creator names, notes or accounts (tested by searching every response for the creator's data), and creator-owned accounts are not offered or accepted as page destinations. Audit rows (`PAGE_CATEGORY_*`, `MANAGED_PAGE_*`, `PAGE_GROUP_*`, `CAMPAIGN_PAGE*`) carry the actor and target and never the free-text notes.
